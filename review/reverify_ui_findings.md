# RIM v0.5.8 UI, input and accessibility re-verification

Reviewed 2 October 2026 (Europe/Berlin). Production code was not edited. Current scripts/scenes were copied into `review/reverify_ui/project`; only the copied Session/Settings paths were redirected to local probe files and the copied project name changed. Original v0.5.6 review snapshot was compared by source diff and never executed.

`ui.gd` differs from the earlier snapshot only by 4 Hz alert throttling. `menu.gd` and `minimap.gd` are unchanged; the Settings difference is the prior probe-only save-path redirection. The new UI checks run on the current v0.5.8 copy with Godot 4.7.2. All 24 prior findings B27–B50 remain open. This is targeted engine/source evidence, not a human accessibility study.

Evidence: R = fresh headless engine fixture; C = source inspection; D = design proposal. R/C explicitly separates observed state from a source-dependent ordinary-player path. Headless rendering cannot establish readability or visual comfort with players. Final engine execution exited 0; the sandbox produced an unrelated Windows certificate-store error. Engine log, probe stdout and structured results are local artifacts.

Artifacts: `review/reverify_ui/project/ui_reverify.gd`, `review/reverify_ui/project/results.json`, `review/reverify_ui/probe.log`, `review/reverify_ui/engine.log`, `review/reverify_ui/proposals.json`. Probe main processing is disabled during most layout tests so fixtures stay stable; UI processing remains live. Camera/input state probes call current dispatchers explicitly. No actual save was opened or changed.

Remaining uncertainty: no manual click-through playtest, rendered screenshots, localization user study, screen-reader session or controller playthrough was performed. UI accessibility metadata proposals require inspecting the real engine accessibility tree.
